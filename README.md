# TelegramCenter

Рассылки и автоответы в Telegram. Один файл `TelegramCenter.exe`, интерфейс —
обычная вкладка браузера на `127.0.0.1`.

## Как это устроено

```
TelegramCenter.exe
├── значок в трее        «Открыть» / «Завершить»; если значок не создался —
│                        маленькое запасное окно с теми же пунктами
├── HTTP-сервер          127.0.0.1:<случайный порт>, только localhost,
│                        каждый запрос с ключом доступа
├── asyncio-поток        Telethon, планировщик кампаний, автоответы, проверки
└── web/dist             собранный React, вшит внутрь exe
```

«Открыть» в меню значка открывает вкладку с ключом доступа в адресе; вкладка
без ключа показывает «Нет доступа». Вкладку можно закрыть — программа
продолжает работать. Останавливается она пунктом «Завершить».

Интерфейс на русском или английском (Настройки → Общие). Ошибки Telegram
переводятся по словарю; ответы ботов (например @SpamBot) показываются как есть.
Логи пишутся по-английски.

## Установка, сборка, запуск

Нужны Python 3.14 и Node 20.

```bat
install.bat     :: venv + pip install + npm ci
build.bat       :: npm run build -> pytest -> PyInstaller -> dist\TelegramCenter.exe
run.bat         :: запуск из исходников (нужен собранный web\dist)
```

`build.bat` останавливается, если падает сборка интерфейса или тесты. В `dist\`
остаётся только exe. Тесты работают во временной папке и никогда не трогают
`%APPDATA%\TelegramCenter`.

Вручную:

```bat
cd web
npm run build
npm test
cd ..
python -m pytest -q
```

`npm test` проверяет логику интерфейса, которой не нужен React (черновик окна,
правило кнопок проверки): TypeScript из сборки и встроенный в Node запуск
тестов, без дополнительных пакетов. `pytest` запускает и их, если в `web\`
установлены пакеты, и проверку того, что окно не сдвигается, в Chrome без окна —
если Chrome установлен; иначе эти тесты пропускаются.

## Данные

```
%APPDATA%\TelegramCenter\
├── data\                 JSON: настройки, аккаунты, операторы, каналы,
│                         кампании, API-профили, прокси, автоответы
├── sessions\campaign\    сессии аккаунтов
├── sessions\operators\   сессии независимых операторов
├── logs\                 логи, файл на каждые сутки
├── media\                картинки сообщений кампаний
└── last_error.txt        текст ошибки, если программа не смогла запуститься
```

Рядом с exe ничего не пишется. Автоматических миграций нет: файлы читаются
текущими моделями, неизвестные ключи настроек отбрасываются.

Файл `.session`, положенный в `sessions\campaign\`, появляется в списке
аккаунтов при следующем запуске или по кнопке «Найти сессии». API-профиля у
такого аккаунта нет — его нужно выбрать, до этого аккаунт не подключается.

## API-профили и прокси

API-профиля по умолчанию нет. Каждый аккаунт подключается только через свой
API-профиль; без него — красная отметка «Нет API-профиля». При входе API нужно
выбрать или ввести; неверные api_id / api_hash видны сразу — Telegram не
отправит код. Удалили API-профиль — его аккаунты выключаются с пометкой.

Статус API-профиля берётся из аккаунтов: хоть один работает — «Работает»;
Telegram отклонил api_id / api_hash — «Ошибка»; иначе — «Не проверен».
Отдельно API-профиль в Telegram не проверяется.

Прокси проверяется кнопкой «Проверить» и при каждой фоновой проверке. Вход в
аккаунт тоже идёт через выбранный прокси.

Правка профиля переподключает аккаунты и операторов, которые через него
работают, только если поменялось то, из чего строится подключение: api_id,
api_hash, протокол, адрес, порт, логин, пароль или «Вкл.». Новое название никого
не переподключает.

## Кампании

Кампания — один аккаунт, список каналов и до 100 сообщений. Каждый канал
получает не тот текст, что ушёл в предыдущий. Список сообщений можно вставить
целиком, разделяя сообщения строкой `===`.

Кампания работает так:

```
«Запустить» (одну или несколько)
  → очередь старта: каждая стартует через случайные 0…«Задержка старта» с
    (Настройки → Кампании, по умолчанию 60) после старта предыдущей
  → Канал 1 → «Интервал» → Канал 2 → «Интервал» → … → Канал N → «Интервал»
  → «По кругу»: снова Канал 1 …
```

* **«Интервал»** (от … до … с) — случайная пауза после **каждого** канала, даже
  если канал пропущен или отправка не удалась: подряд запросов нет.
* Режимы: **«По кругу»** — проходы до остановки; **«Один раз»** — один проход в
  указанные дату и время; **«Ежедневно»** — один проход в каждое указанное
  время (ЧЧ:ММ). Очередь старта действует только для «По кругу».
* Если в «Ежедневно» проход ещё идёт, а наступило следующее время, это время
  пропускается и пишется в лог.
* Кампании друг друга не ждут.
* Запускает кампанию только кнопка «Запустить». Останавливает — «Остановить»
  или проблема, которая мешает отправлять: аккаунт выключен или его сессия
  аннулирована, пропали каналы, сообщения или оператор для `@operator`.
  Причина видна в окне результатов. Сама кампания обратно не запускается.
* После перезапуска программы кампании, которые работали, продолжаются:
  «По кругу» и прерванный проход снова встают в очередь старта, дата или время,
  пропущенные пока программа была закрыта, выполняются сразу.

Одно сообщение в один чат отправляется так: аккаунт появляется в сети,
открывает и читает чат, иногда ставит реакцию на последнее сообщение (до
своего, поэтому никогда на своё), «печатает» столько, сколько набирался бы
текст, отправляет и уходит из сети. «Печатает», «прочитано», «в сети» —
вежливость: их ошибки никогда не влияют на результат отправки. Отказ реакции
учитывается, только если он про сам аккаунт (бан, FloodWait, мёртвая сессия,
заморозка) — тогда сообщение не отправляется, а отказ разбирается как отказ
отправки.

Кроме интервала программа соблюдает только то, что требует сам Telegram, и
шлёт с одного аккаунта одно сообщение за раз; никакие ожидания не держат
остальные кампании аккаунта. Настройки → Кампании:

* подписываться на канал перед отправкой и пауза после подписки;
* иногда ставить реакции в чатах кампании;
* «Страховка»: аккаунт выключается, если за час не прошла заданная доля
  отправок (при минимуме отправок). Считаются только ошибки аккаунта и сети;
  один и тот же чат до следующей удачной отправки считается один раз.
  Включение аккаунта вручную начинает счёт заново.

Выключенный канал (вкладка «Каналы», «Вкл.») кампании не трогают. Канал,
выключенный внутри кампании, остаётся в общем списке каналов; вернуть его —
галочкой в окне результатов или кнопкой «Сбросить».

### Когда Telegram отказывает

| Что ответил Telegram | Что делает программа |
|---|---|
| Бан в чате (проверяется одним запросом к чату после отказа) | Если запрет больше 7 дней или навсегда — канал выключается во всех кампаниях этого аккаунта («Забанен в чате»), аккаунт выходит из чата (для канала с комментариями — и из обсуждения, и из канала). До 7 дней — канал пропускается до конца срока («Пропущено · запрет до …») |
| «Забанен», но чат ничего не запрещает | Telegram запретил аккаунту писать в публичные группы: аккаунт выключается, его кампании останавливаются, каналы и чаты не трогаются |
| Медленный режим чата | Канал пропускается до указанного времени во всех кампаниях аккаунта («Пропущено · slow mode до …»); остальные каналы идут дальше |
| FloodWait | Ждёт весь аккаунт: кампании и автоответы продолжают сами, когда время выйдет. Статус аккаунта «Ожидание Telegram до …», время хранится у аккаунта и переживает перезапуск; «Остановить» срабатывает сразу |
| Такого чата нет (ник не существует, ссылка недействительна) | Канал выключается во всех кампаниях всех аккаунтов, у канала статус «Не найден» |
| Комментарии только для вступивших в обсуждение, автоподписка выключена | Канал выключается во всех кампаниях, у канала статус «Нужна подписка» |
| Аккаунт не в группе, автоподписка выключена | Сообщение не отправляется, канал выключается в кампании («Аккаунт не в чате»). Комментарии в канал пробуются и без вступления |
| Прочие отказы чата (писать запрещено, чат закрыт и т. п.) | Считаются подряд; после трёх подряд канал выключается в кампании (`campaign.refusals_before_off` в `settings.json`) |
| Сессия аннулирована, аккаунт заморожен | Аккаунт помечается, его кампании останавливаются |
| Сеть, прокси, таймаут, прочее | Идёт в «Страховку» |

Время ожидания пишется «14:35», если это сегодня, и с датой — если нет.

Массовое «Изменить» у кампаний: не отмеченные каналы — у каждой кампании свои;
отмеченные — заменяют список у всех выбранных.

## Аккаунты и операторы

* **Аккаунт** — с него уходят сообщения кампаний и автоответы.
* **Оператор** — тот, кому передают клиента; `@operator` в текстах заменяется
  его ником. Достаточно ника; оператор с сессией открывает ещё и чаты.

Оператор бывает двух видов:

* **Связанный** — сделан из аккаунта («Сделать оператором»). Хранит только
  ссылку на аккаунт и заметки. Сессия, API, прокси, статус и проверки — у
  аккаунта; файл сессии один, в `sessions\campaign\`. API и прокси можно менять
  и в окне оператора, и в окне аккаунта — это одна настройка.
* **Независимый** — добавлен по нику или через «Войти в аккаунт» на странице
  операторов. Всё своё; сессия в `sessions\operators\`.

Одна сессия никогда не хранится в двух файлах: один ключ в двух файлах и два
подключения с разных адресов — то, за что Telegram аннулирует ключ
(`AuthKeyDuplicatedError`). Поэтому:

* вход в «Аккаунтах» Telegram-аккаунтом, который уже есть как независимый
  оператор, завершает старую сессию оператора и делает его связанным;
* вход «как оператор» аккаунтом, который уже есть в «Аккаунтах», не создаёт
  нового файла — оператор становится связанным;
* удаление связанного оператора аккаунт не трогает; при удалении аккаунта
  окно спрашивает, оставить ли его оператора как ник;
* выключенный аккаунт выключает и связанного оператора.

Аннулированную сессию проверка не чинит — только повторный вход; карточка
аккаунта или оператора предлагает «Войти заново».

### Окна правки

Окно аккаунта, оператора, API-профиля или прокси — черновик поверх записи:

* «Сохранить» отправляет всё изменённое одной командой, «Отмена» отбрасывает
  всё, в том числе «Свой автоответ» в окне аккаунта.
* Кнопки внутри окна — «Проверить аккаунт», «Сделать оператором», «Войти
  оператором» — сначала сохраняют изменения окна. Включили аккаунт
  переключателем — «Проверить аккаунт» уже доступна; нажатие включает аккаунт
  и проверяет его, окно остаётся открытым с результатом.
* Аккаунт сохраняется в одном порядке: выключение — первым, включение —
  последним. Подключение идёт только с итоговыми API и прокси: выключить
  аккаунт и сменить ему прокси не подключает его через новый прокси «на
  выходе».
* Если программа сама меняет запись, пока окно открыто (например, выключила
  аккаунт по спам-проверке), окно это показывает, и «Сохранить» её решение не
  отменяет. Поля, которые вы не трогали, всегда показывают текущее.
* Отказ показывается в самом окне; окно остаётся открытым со всем введённым.
* Окно открывается на одном месте и не сдвигается, когда в нём что-то
  появляется: оно растёт вниз, а не хватает высоты — прокручивается внутри.

Пакетная правка аккаунтов (API, прокси, оператор) и операторов (API, прокси) —
тоже одна команда: каждый аккаунт переподключается один раз, уже с новыми API
и прокси. Несуществующий профиль отклоняется до каких-либо изменений.

## Автоответы

Один набор правил на аккаунт; аккаунты без своего отвечают общим. Правила:
«Первое сообщение» (один раз на собеседника), «Периодический ответ» (не чаще
одного раза за задержку) и «Вопрос–ответ» по ключевому слову (лимит в
настройках). Задержка ответа — случайная, в заданном диапазоне. Страница
сохраняет изменения сама: через секунду после ввода, при смене аккаунта и при
уходе со страницы.

Ответ с `@operator` у аккаунта без оператора не отправляется, а страница
об этом предупреждает; правило при этом не выключается.

Кто написал впервые, пока программа, аккаунт или автоответ были выключены,
получает ответ при включении — если чат не прочитан, собеседник раньше не
писал и сообщению меньше суток. Перед ответом аккаунт появляется в сети,
читает чат, «печатает» и после отправки уходит из сети. Если Telegram велел
аккаунту подождать (FloodWait), ответ ждёт вместе с ним и уходит после.

## Проверки

Одна проверка для кнопок и для фона. Одновременно идёт не больше одной.

* **Кнопки**: «Проверить все» на страницах аккаунтов, операторов и каналов,
  «Проверить» у выбранных, «Проверить аккаунт» в его окне, «Проверить спам» в
  настройках. Каждая страница показывает прогресс только своей проверки.
* **Фон**: раз в случайное время из «Интервала фоновой проверки» (по
  умолчанию 15–30 мин) — прокси, аккаунты и независимые операторы. Фон никогда
  не пишет @SpamBot.
* Кнопка во время фоновой проверки останавливает её: кого фон не успел
  проверить, тем возвращается прежний статус. Поэтому фоновая проверка кнопки
  не блокирует — ждать приходится, только пока идёт проверка, запущенная
  другой кнопкой.
* Проверка, которая не может начаться — идёт проверка другой кнопки или
  проверять нечего (все выбранные аккаунты выключены, каналов нет), —
  называет причину, а не молчит.
* Перед подключением каждый аккаунт ждёт случайное время из «Разброса
  подключения» — и в фоне, и по кнопке.
* Связанный оператор проверяется вместе со своим аккаунтом.
* **Выключенный аккаунт полностью выключен**: ни подключения, ни проверок, ни
  спам-проверки, ни автоответов, ни кампаний. «Проверить аккаунт» у него
  недоступна, пока переключатель в окне стоит на «Выключено». Выключила
  программа — причина в подсказке у статуса.

Предупреждение «молодой аккаунт» появляется сразу после добавления и держится
заданное число дней от даты добавления в программу.

### Проверка на спам-ограничения

Включается в настройках (по умолчанию выключена: она отправляет сообщение с
каждого аккаунта). Тогда кнопки проверки дополнительно спрашивают бота (по
умолчанию `@SpamBot`), а «Проверить спам» спрашивает только его: уходит
`/start`, ответ разбирается по фразам из настроек — их можно поменять без
пересборки, пустой список возвращает встроенные. Бот отвечает то по-английски,
то по-русски, поэтому понимаются оба языка; непонятный ответ помечается
отдельно и никогда не считается «чисто».

После ответа нажимается кнопка «Cool, thanks» / «Хорошо, спасибо», иначе бот
ждёт нажатия и на следующий `/start` не отвечает. Кнопки апелляции не
нажимаются никогда.

Найденное ограничение **выключает аккаунт**; его кампании останавливаются.
Когда ограничение снято, аккаунт включают тем же переключателем — это значит
«я разобрался», старые отметки снимаются. Кампании запускаются вручную.

## Логи

Страница «Логи» показывает последние строки и новые по мере появления.
Все строки пишутся и в файлы `logs\ГГГГ-ММ-ДД.log`: один файл на календарные
сутки, новый — с полуночи, хранятся 14 последних. Время в строке:
`2026-09-25T-22:33:06`. Строки кампаний называют и кампанию, и аккаунт:
`'Main' [@sender] -> Chat: sent (msg_…)`.
