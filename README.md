# TelegramCenter

Рассылки и автоответы в Telegram. Один файл `TelegramCenter.exe`, интерфейс
открывается обычной вкладкой браузера на `127.0.0.1`.

## Как это устроено

```
TelegramCenter.exe
├── значок в трее        меню «Открыть» / «Завершить», иконка icon.ico
├── HTTP-сервер          127.0.0.1:<случайный порт>, только localhost
├── asyncio-поток        Telethon, планировщик кампаний, автоответы
└── web/dist             собранный React, вшит внутрь exe
```

Вкладку браузера можно закрыть — backend продолжает работать и рассылать.
Приложение останавливается пунктом «Завершить» в меню значка.

Все данные — в `%APPDATA%\TelegramCenter`. Рядом с exe ничего не пишется.

## Установка и сборка

Нужны Python 3.14 и Node 20.

```bat
install.bat     :: venv + pip install + npm ci
build.bat       :: npm run build -> pytest -> PyInstaller -> dist\TelegramCenter.exe
```

`build.bat` останавливается, если падают тесты. В `dist\` остаётся только exe,
промежуточные файлы из `build\` удаляются. `%APPDATA%` при сборке не трогается.

Запуск из исходников: `run.bat`.

## Данные

```
%APPDATA%\TelegramCenter\
├── data\                 JSON: аккаунты, кампании, каналы, шаблоны, автоответы
├── sessions\campaign\    сессии аккаунтов рассылки
├── sessions\operators\   сессии операторов
└── instance.json         порт и адрес запущенного экземпляра
```

Чтобы добавить аккаунт, можно просто положить файл `.session` в
`sessions\campaign\` — при следующем запуске он появится в списке.

При первом запуске v2 данные из v1 переносятся автоматически, а копия старой
папки `data\` сохраняется в `data.v1.bak\` — её можно удалить вручную.

## Две роли аккаунтов

* **Аккаунт рассылки** — с него уходят сообщения кампаний, к нему привязаны
  автоответы.
* **Оператор** — тот, кому передают клиента. Достаточно ника; если войти в
  аккаунт, дополнительно открываются чаты с возможностью отвечать.

В любом тексте можно писать `@operator` — он заменяется на ник привязанного
оператора. Если оператора нет, правило нельзя ни сохранить, ни включить, и
сообщение не уйдёт: буквальный `@operator` до собеседника не доходит.

## Проверка на спам-ограничения

Кнопка «Проверить все» проверяет аккаунты на работоспособность. Если в
настройках включить «Проверка спама», она дополнительно спросит у бота Telegram
(по умолчанию `@SpamBot`), не наложены ли на аккаунт ограничения: боту уходит
`/start`, его ответ разбирается.

Приложение просит у Telegram английский, но решение за Telegram: Telethon
обязан отправлять пустой `lang_pack`, которым официальные клиенты закрепляют
язык. На практике один и тот же аккаунт отвечает то по-английски, то
по-русски, поэтому разбираются оба языка. Ответ на любом другом языке
помечается как непонятный, а не угадывается.

После ответа приложение нажимает кнопку «Cool, thanks», закрывая диалог: иначе
бот остаётся ждать нажатия и на следующий `/start` отвечает «Please use buttons
to communicate with me». Если диалог всё же завис, проверка повторяется один
раз, а затем честно сообщает, что бот ждёт кнопку. Кнопки апелляции не
нажимаются никогда.

Аккаунты проверяются по очереди с настраиваемой паузой (по умолчанию 5 секунд).
Найденное ограничение показывается там же, где и остальные проблемы аккаунта:
кружок перестаёт быть зелёным, а в подсказке видно формулировку самого Telegram
вместе с датой снятия. Ответ, который приложение не смогло разобрать, помечается
отдельно — «чисто» по умолчанию не выставляется никогда.

Фразы, по которым распознаётся ответ, лежат в настройках и редактируются:
сменили бота — поменяли и ожидаемые ответы, пересборка не нужна. Пустой
список возвращает встроенные формулировки.

**Найденное ограничение выключает аккаунт**, а вместе с ним и его кампании.
Включить обратно — тем же тумблером в настройках аккаунта: включение считается
за «я разобрался», старая отметка снимается, кампании возвращаются сами.
Чтобы убедиться, что ограничение снято, не включая аккаунт, есть кнопка
«Проверить этот аккаунт» в его настройках — общая проверка выключенные
аккаунты не трогает.

Функция выключена по умолчанию: она отправляет сообщение с каждого аккаунта.

## Зависимости всё связывают

`API-профиль → Аккаунт → Кампании и Автоответы`, `Прокси → Аккаунт`,
`Оператор → Аккаунт`.

Если ломается API-профиль или прокси, аккаунт немедленно становится ERROR, а
его кампании — заблокированными. Состояние не хранится, а вычисляется при
каждом чтении, поэтому «прокси упал, а рассылка идёт» невозможно.

Все ошибки показываются цветным кружком, текст — во всплывающей подсказке при
наведении.
